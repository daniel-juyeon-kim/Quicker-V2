## 문제

새로운 기능을 개발할 때 수동 테스트에 의존했습니다. 그러다가 기존 코드를 리팩토링하면서 다음과 같은 문제가 있었습니다.

- 리팩토링이 기존 기능에 영향을 주어 동작이 달라짐
- 수동 테스트는 일시적이고 시간이 오래 걸림
- 일부 예외 상황이 배포 이후 발견

## 해결

반복적 검증을 위해 테스트 코드를 작성했습니다. 레포지토리 계층은 **인메모리 SQLite**를, 외부 API 어댑터는 **모킹**으로 외부 환경에 영향을 받지 않도록 했습니다.

### 레포지토리 계층 테스트

레포지토리 계층 테스트 환경으로 인메모리 SQLite와 Docker 기반 테스트 DB를 비교했습니다.

#### 인 메모리 DB 장단점

장점

- **테스트 속도 빠름**
- 설정 적음

단점

- 배포와 테스트 환경의 DB가 다름

#### Docker 기반 테스트 DB 장단점

장점

- 배포 환경과 동일한 DB 사용

단점

- 상대적으로 **테스트 속도 느림**
- Docker 및 CI 환경 설정 필요

### 외부 API 어댑터 테스트

외부 API 어댑터는 **사용 요금, IP 화이트리스트, 네트워크 및 API 서버 상태에 따라 테스트 결과가 달라질 수 있습니다.** 이때 **모킹**을 사용할 수 있습니다.

모킹은 의존성을 가짜로 만들고 동작을 가정해 테스트하는 방법으로 외부환경에 영향을 받지 않아 테스트 결과가 달라지지 않는 장점이 있지만 실제 동작이 아니므로 주의해서 사용해야 합니다.

프로젝트에서는 Slack, Naver SMS, Tmap 등의 외부 API 어댑터를 모킹하고 테스트했습니다.

## 성과

테스트 코드를 도입하면서 다음 결과를 얻었습니다.

- **257개 테스트 통과, Statements 기준 코드 커버리지 94.78%** 
- 리팩토링이 기존 기능에 미치는 영향 확인 가능
- 수동 테스트에 소비되는 시간을 개발에 투자 가능
- 수동 테스트에서 놓치는 엣지 케이스 감소
